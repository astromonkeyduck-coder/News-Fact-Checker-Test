# Article companion backend contract

The new modes opt in explicitly. General image classification, chat tools and general voice behavior remain unchanged.

`POST /.netlify/functions/noteworthy-chat` with `{articleImage:true,message,pageContext:{articleId}}` loads the exact stored article first, applies `publicationAiGrounding.projectArticle`, checks its identity and excludes records withheld by the public publication rules. Missing, mismatched, empty, draft or review records return HTTP 409 with `groundingUnavailable:true`. Browser titles, URLs, uploaded files and chat history do not supply factual image context. Attachments are rejected for this mode.

Eligible article images use `gpt-image-2.5-sunburst` through the Images API with a 1024×1024 PNG at medium quality. The source excerpt is capped at 10,000 characters and explicitly marked when truncated. The prompt asks for a source-limited teaching schematic, retains attribution and uncertainty, prohibits documentary reconstructions and invented specifics, and asks for an AI/not-evidence label. These are generation instructions, not a guarantee of factual or visual accuracy. The response always supplies an independent label for the UI to display.

Success is `{reply,image:{imageUrl,aiGenerated:true,label,articleId,articleUrl,prompt,revisedPrompt}}`. `imageUrl` is a `data:image/png;base64,...` value; the server validates base64, PNG signature and a 4,000,000-character limit. `prompt` is the reader's bounded explanatory request; `revisedPrompt` is optional provider text, not verification. The image is not written to Blobs or the article record by this mode. The server returns explicit `imageGenerationFailed:true` errors for provider failure, invalid output, oversize response and the 45-second provider timeout. There is no automatic generic-image fallback or second chat request. The existing chat rate limit still applies.

`POST /.netlify/functions/story-voice-session` with `{pageContext:{articleId}}` uses ElevenLabs for an article conversation and shares the eligible article source loader. It requires server-only `ELEVENLABS_API_KEY` and `ELEVENLABS_AGENT_ID`; missing configuration returns 503 with `voiceUnavailable:true`. It obtains a WebRTC token from ElevenLabs using the configured agent ID and returns `{provider:'elevenlabs',conversationToken,overrides,articleId,articleUrl}`. Missing source material returns 409 before token generation. Provider failure is explicit, with a 10-second timeout. There is no OpenAI voice fallback. The original general-purpose `realtime-voice.js` has no changes from this feature.

The configured ElevenLabs agent must permit **System prompt, First message, Tools, Knowledge base and Language** overrides in its Security settings. The official client must pass the returned `overrides` to `Conversation.startSession({conversationToken,overrides})`. The response supplies `overrides.agent.prompt` with `prompt`, `tool_ids:[]` and `knowledge_base:[]`, plus `agent.firstMessage` and `agent.language`. The pinned `@elevenlabs/client@1.25.0` forwards the nested prompt object unchanged and converts `firstMessage` to its wire name; the nested arrays therefore use snake_case. Empty arrays replace inherited tool/knowledge-base lists. Do not retry a failed override handshake by dropping the overrides.

The returned prompt identifies the speaker as AI, limits event-specific claims to the supplied article and discloses unavailable details. The token itself does not bind this prompt; the normal client sends the server-authored overrides during connection. This does not implement independent fact checking or constrain a modified third-party client. No agent creation or configuration update is performed by the endpoint.

`POST /.netlify/functions/elevenlabs-tts` with `{storyAnswer:true,text}` speaks one answer chunk. The frontend sends ordered chunks of at most 900 characters; the server rejects chunks over 1,000 characters instead of silently shortening them. The request uses the existing ElevenLabs voice/model and has a 20-second timeout, including audio-body download. The original snippet cap and cached article narration remain available.

Checked against official API documentation on September 13, 2026: [image generation and PNG/base64 format](https://developers.openai.com/api/docs/guides/image-generation), [GPT Image 2.5 Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst), [ElevenLabs conversation token](https://elevenlabs.io/docs/eleven-agents/api-reference/conversations/get-webrtc-token), [ElevenLabs SDK](https://elevenlabs.io/docs/eleven-agents/libraries/java-script), and [ElevenLabs override setup and wire fields](https://elevenlabs.io/docs/eleven-agents/customization/personalization/overrides).

Validation: `node --test tests/publication/article-companion-backend.test.js tests/publication/ai-grounding.test.js` passed 24/24 tests. Tests isolate credentials and mock all storage/provider calls, including full image/ElevenLabs session contracts, missing configuration, fail-before-provider behavior, complete answer chunks and preservation of the legacy snippet cap and generic voice tools. No live model, image, microphone or paid service call was made. Deployment still needs credential/model access, an ElevenLabs agent with the stated override settings, real latency and output-quality checks. The deployed function duration must permit the 45-second image timeout plus source lookup; a shorter platform cap can terminate the request before the structured timeout response.
